# 人狼 中継サーバー(jinro-server)

人狼のオンライン対戦で使う中継サーバーです。Cloudflare Workers と Durable Objects で動きます。

- 各プレイヤーは、このサーバーとだけ WebSocket でつながります。端末どうしは直接つながらないので、相手にIPアドレスは見えません。
- 役職・夜の行動・投票先は、サーバーだけが持ちます。各プレイヤーには「公開情報+その人だけの秘密」だけを送ります。
- 秘密の値(APIキーなど)は使いません。

## ファイルの置き場所

ゲームとサーバーは、別々のリポジトリに置きます。どれもフォルダに入れず、リポジトリの一番上に置いてください。

| ファイル | 置くリポジトリ | 役割 |
|---|---|---|
| `index.html` | ゲームのリポジトリ(GitHub Pages で公開) | ゲーム本体 |
| `index.js` | `jinro-server` | サーバーのプログラム |
| `wrangler.jsonc` | `jinro-server` | サーバーの設定 |
| `README.md` | `jinro-server` | この説明 |

> `index.html` と `index.js` は名前が似ています。ゲームのリポジトリには `index.html` だけを置きます。

## スマホでの公開手順

### 1. サーバーのリポジトリを作る(GitHub)

1. ブラウザで github.com を開き、右上の「+」から「New repository」を選びます。
2. Repository name に `jinro-server` と入れて「Create repository」を押します(公開・非公開はどちらでもかまいません)。
3. 「uploading an existing file」(または「Add file」→「Upload files」)を押します。
4. `index.js`、`wrangler.jsonc`、`README.md` の3つを選んでアップロードし、「Commit changes」を押します。

### 2. Cloudflare に公開する

1. ブラウザで dash.cloudflare.com を開いてログインします。スマホでは、ブラウザのメニューから「PC版サイト」に切り替えると操作しやすくなります。
2. 左のメニューの「Workers & Pages」から「作成(Create)」を押します。
3. 「リポジトリをインポート(Import a repository)」を選び、GitHub と連携して `jinro-server` を選びます。
4. プロジェクト名が `jinro-server` になっていることを確かめます。ビルドコマンドは空、デプロイコマンドは最初から入っている `npx wrangler deploy` のままで「デプロイ」を押します。
5. 終わったら `https://jinro-server.jh0ndo3.workers.dev/` を開きます。「人狼 中継サーバー:動作中」と出れば成功です。

これ以降は、GitHub の `jinro-server` のファイルを書き換えると、自動で公開し直されます。

### 3. ゲームを公開する(GitHub Pages)

1. ゲーム用のリポジトリを作り、`index.html` を一番上にアップロードします。
2. そのリポジトリの「Settings」→「Pages」で、Source を「Deploy from a branch」、Branch を `main` と `/(root)` にして「Save」を押します。
3. 1〜2分待ってから `https://<GitHubのユーザー名>.github.io/<リポジトリ名>/` を開きます。
4. 「オンライン対戦」→「新しいルームを作る」で、ルームIDが出れば成功です。

サーバーのアドレスは、`index.html` のスクリプトの冒頭にある `SERVER_URL` に入っています(秘密ではありません)。サーバーの名前を変えた時は、ここも直してください。空にすると、オンライン対戦は理由を表示して使えなくなります。

### 4. 使えるサイトを限定する(おすすめ)

最初は `ALLOWED_ORIGINS` が空なので、どのサイトからでもサーバーを使えます。ゲームの公開が済んだら、自分のサイトだけに限定しておきます。

1. GitHub の `jinro-server` で `wrangler.jsonc` を開き、鉛筆のボタンで編集します。
2. `"ALLOWED_ORIGINS": ""` を、ゲームのサイトのアドレスに書き換えます。
   ```
   "ALLOWED_ORIGINS": "https://<GitHubのユーザー名>.github.io"
   ```
   - 書くのは `https://〜.github.io` までです。リポジトリ名や、最後の `/` は付けません。
   - 複数のサイトを許可する時は、カンマで区切ります。
3. 「Commit changes」を押すと、自動で公開し直されます。

## 遊び方の要点

- 4〜20人で遊べます。観戦はありません。
- ルームID(4文字)か招待リンクで同じルームに入り、席を選びます。席が全部埋まると、席にいる誰でも「対局開始」を押せます。
- 夜の行動と投票は、全員が自分のスマホで同時に行います。
- 昼の議論は、生存者の過半数が「議論を終えて投票へ」を押すと投票に進みます。時間切れの後は1人で進められます。
- 待ったはありません。投了すると「突然死」になり、その人は死亡します。役職は終局まで明かされません。
- 「死亡した人の画面」は、開始前に設定します。
  - 全員の役職を見られる(既定)
  - 公開情報だけ
- 通信が切れても自動でつなぎ直します。ページを閉じた時も、メニューの「続きの対局」から戻れます。
- 7日間使われていないルームは、自動で消えます。

## うまくいかない時

| 症状 | 確かめること |
|---|---|
| 「再接続中…」のまま | `https://jinro-server.jh0ndo3.workers.dev/` に「動作中」と出るか。`ALLOWED_ORIGINS` のアドレスが、ゲームを開いているサイトと一字一句同じか(`https`、最後に `/` なし)。 |
| デプロイで Durable Objects のエラーが出る | `wrangler.jsonc` の `migrations` が `new_sqlite_classes` になっているか(無料プランではこれが必要です)。 |
| 「ルームが見つかりません」 | ルームIDの打ち間違い(I・O・0・1 は使いません)か、7日以上使われずに消えたルーム。 |
| オンライン対戦のボタンを押すと SERVER_URL の案内が出る | `index.html` の `SERVER_URL` が空になっていないか。 |

## ルールを変える時

ゲームのルールは、`index.html`(1台を回すモードと画面)と `index.js`(オンライン対戦の正本)の両方にあります。片方だけを直すと、オンライン対戦と1台のモードで動きが変わってしまいます。必ず両方を同じように直してください。どちらのファイルにも、その旨のコメントがあります。
